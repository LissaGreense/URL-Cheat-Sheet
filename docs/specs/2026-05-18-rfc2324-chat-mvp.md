# RFC 2324 Chat MVP — Design

**Status:** Approved (brainstorm). Next: implementation plan.
**Date:** 2026-05-18

## Goal

Build the first working slice of URL-Cheat-Sheet: a chat app where the
user asks questions and a backend agent answers them grounded in
**RFC 2324 (Hyper Text Coffee Pot Control Protocol, HTCPCP)**. The RFC is
bundled with the build — no URL fetcher yet. The agent has exactly one
tool: a literal substring grep over the bundled text.

This slice is intentionally small and end-to-end. It stands up the
`chat UI → endpoint → agent → tool` plumbing so subsequent iterations
(real URL fetch, multi-doc, citations UI) plug into a working spine.

## Explicit non-goals for v1

- URL fetcher (the next iteration)
- Multiple documents
- Citation-rendering UI (line numbers are surfaced inline in the
  assistant text)
- Auth, rate limiting
- Chat persistence (history wipes on reload — pure in-memory client state)
- Real-LLM eval harness wiring (lives in `packages/evals/`, future work)

## Architecture

```
apps/web/
  src/routes/api/chat/+server.ts   ← SvelteKit endpoint, streams agent output
  src/routes/+page.svelte          ← chat UI via @ai-sdk/svelte
packages/agent/
  src/data/rfc2324.txt             ← committed static document
  src/tools/grep-rfc.ts            ← the one tool
  src/prompt.ts                    ← system prompt
  src/agent.ts                     ← streamChat() entry
  tests/                           ← unit tests
```

The RFC text lives **with the agent package**, not in `apps/web/static`.
It does not need to be publicly served. It is bundled into the server
bundle via Vite's `?raw` import:

```ts
import rfc from './data/rfc2324.txt?raw';
```

This works in dev and on Vercel without filesystem assumptions.

## Data flow

1. User types in the chat UI → `Chat` client (`@ai-sdk/svelte`) posts
   `{ messages }` to `/api/chat`.
2. `+server.ts` validates the body with Zod, then calls
   `agent.streamChat(messages)`.
3. `streamChat` invokes
   `streamText({ model: anthropic('claude-sonnet-4-6'), system, messages, tools: { grep_rfc }, stopWhen: stepCountIs(5) })`.
4. The model decides whether to call `grep_rfc` (zero or more times). The
   tool runs the substring match against the bundled string and returns
   line hits plus context.
5. The model composes an answer, citing the line numbers it used inline.
6. The endpoint returns `result.toUIMessageStreamResponse()`. The UI
   renders tokens as they arrive.

The API key (`ANTHROPIC_API_KEY`) lives on the server only. It is never
sent to the browser.

## Component contracts

### `grep_rfc` tool

```ts
// packages/agent/src/tools/grep-rfc.ts
input: z.strictObject({
  pattern: z.string().describe('Case-insensitive substring to search RFC 2324.'),
})

output: z.strictObject({
  matches: z.array(z.object({
    line: z.number(),
    text: z.string(),
    before: z.array(z.string()),   // up to 2 lines preceding the hit
    after: z.array(z.string()),    // up to 2 lines following the hit
  })),
})
```

Hardcoded behavior:

- Literal substring only — no regex.
- Case-insensitive.
- 2 lines of context above and below each hit.
- Silently capped at 20 matches. The model is not told about the cap; if
  it cares about exhaustiveness it can refine the pattern.

Empty `matches: []` is the only "no result" signal. No error variant —
invalid input cannot occur for a free-form string.

### System prompt

> You answer questions about RFC 2324 (Hyper Text Coffee Pot Control
> Protocol, HTCPCP). Use the `grep_rfc` tool to ground every factual
> claim before answering. Cite the line number(s) you used inline
> (e.g., "see L142"). If grep returns no relevant matches, say so
> honestly — do not guess from prior knowledge. The grep tool is a
> literal case-insensitive substring search — phrase patterns as plain
> text, not regex. Keep answers concise; assume plain-text rendering
> (no markdown).

### Chat endpoint

```ts
// apps/web/src/routes/api/chat/+server.ts
POST body: z.strictObject({ messages: z.array(UIMessageSchema) })
```

- 400 on Zod failure.
- 500 if `ANTHROPIC_API_KEY` is missing — fail fast with a clear message
  in dev.
- Otherwise stream the response via `result.toUIMessageStreamResponse()`.
- Tool-call loop bounded by `stopWhen: stepCountIs(5)`. If the bound
  trips, the partial answer streams normally and the model self-reports.

### Chat UI

`apps/web/src/routes/+page.svelte`:

- Single `<Chat>` instance from `@ai-sdk/svelte`.
- Message list + input box.
- Plain-text rendering of assistant turns (no markdown renderer in v1 —
  the system prompt tells the model to keep formatting minimal).
- Tool calls rendered as a collapsed `<details>` element for
  transparency.
- No persistence — page reload wipes state.

## Error handling

| Failure | Behavior |
|---|---|
| Missing `ANTHROPIC_API_KEY` | `/api/chat` returns 500 with `"ANTHROPIC_API_KEY not set"` |
| Malformed request body | 400 with Zod error message |
| Tool returns 0 matches | Model says so per system prompt |
| Tool step count exceeded | Partial answer streams; model self-reports the truncation |

## Testing

- `packages/agent/tests/grep-rfc.test.ts` — unit tests: literal hit, no
  match, context boundaries (first line, last line, middle), case
  insensitivity, 20-match cap.
- `packages/agent/tests/agent.test.ts` — wiring check: system prompt is
  set, tool is registered, model adapter is the Anthropic one. The
  model itself is mocked.
- `apps/web/tests/chat-route.test.ts` — endpoint: 400 on bad body,
  500 on missing key, 200 on valid input. Agent mocked.

No live-LLM tests in v1. Live evaluation belongs in `packages/evals/`.

## Pipeline mapping

This brainstorm decomposes into a small epic plus ~5 tasks:

| # | Title | Notes |
|---|---|---|
| 1 | Bundle RFC 2324 with the agent package | Download, commit, wire Vite `?raw` import |
| 2 | Implement `grep_rfc` tool with tests | Unit-tested in isolation |
| 3 | Implement `streamChat` agent with system prompt | Tool wired in, model mocked in tests |
| 4 | Implement `/api/chat` SvelteKit endpoint | Zod-validated body, streaming response |
| 5 | Implement chat UI on `+page.svelte` | `@ai-sdk/svelte` `Chat`, plain text rendering |

Each item flows through the standard pipeline
(plan → tasks → impl → review → QA → merge).

## Open questions

None blocking. Future considerations (out of v1 scope):

- When we add a URL fetcher, does the grep tool gain a `documentId`
  parameter or do we keep one tool instance per loaded document?
- When citations get their own UI, the grep tool output may need an
  immutable "passage id" instead of mutable line numbers.
